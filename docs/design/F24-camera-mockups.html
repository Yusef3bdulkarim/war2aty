F24 · Camera redesign — three variants

Each phone is live. Tap the paper to focus, tap ⚡ to toggle the light, tap the shutter to take a shot. The toolbar puts all three phones in the same state so they can be compared side by side. Same constraints for all three: Waraqti palette and Cairo, Arabic RTL, the feed letterboxed (Fit) exactly as today, every control at least 48 × 48, and no state shown by colour alone.

Layout
Photos, shutter and light sit in one translucent capsule floating over the bottom band. Close is alone at top-start.
Light on
The button turns mint with a plain ⚡, and a «الفلاش شغال» chip appears at the top centre. On a phone with no flash the light button disappears but keeps its slot, so the shutter never moves.
Focus
White corner brackets, echoing the viewfinder language users already know from scanner apps.
Trade-off
The most polished look, but the blur needs a BackdropFilter in Flutter, which costs a little on low-end phones. Icons only, apart from the chip.

Behaviour the mockups had to pick — please confirm or change

These are placeholders so the screens could be drawn. None of them is decided.

  1. Light or flash? All three show a two-state light (a torch that stays on while framing, so you see the result before shooting). The alternative is a classic flash that fires only with the shutter (off / auto / on).
  2. Photos button: a plain icon, which needs no new permission. A thumbnail of the latest photo would need access to the photo library.
  3. Hint: only B brings a hint back. A and C have none.
  4. Camera error page: all three add «اختار صورة من الموبايل» under «حاول تاني», since the error message already tells the user to do that. Today the page has only the retry.
  5. Phone without a flash: A and C hide the light but keep its space, so the shutter stays put. B shows it greyed out as «مفيش فلاش».
  6. Light after a shot: whether it stays on when the user comes back from the crop screen, or always starts off.
