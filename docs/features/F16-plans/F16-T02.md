## Design decisions (settle here, don't re-open later)

1. **Corner storage is ordered, not a list.** `topLeft / topRight / bottomRight
   / bottomLeft` as named fields, so no consumer has to remember an index
   convention. The unordered entry point is the factory below.
2. **`DocumentQuad.fromPoints(List<UnitPoint>)`** takes 4 points in any order and
   sorts them TL/TR/BR/BL: compute the centroid, sort by `atan2(y - cy, x - cx)`,
   then rotate the cycle so it starts at the point closest to the origin.
   Returns `null` for anything that is not exactly 4 points. This is the only
   place ordering logic lives — T03 hands it raw hull corners.
3. **`isValid`** = convex **and** non-degenerate: all four cross-products of
   consecutive edges share a sign (convex), `area >= minArea` (default `0.05` of
   the frame), and no two corners closer than a small epsilon. `area` via the
   shoelace formula. `minArea` is a named parameter with a const default so T03
   and T09 can tighten it without editing the entity.
4. **`boundingRect` → `UnitRect`** (min/max of the four corners, `.clamped()`).
   This is the bridge to the existing crop path — T08 feeds it straight into
   `CropToGuideBox`, which already applies the 20% margin. No new margin concept.
5. **`lerpTo(DocumentQuad other, double t)`** — per-corner linear interpolation,
   added *now* even though only T06 consumes it, so the entity is not re-opened
   for a two-line method later. It is pure math and belongs with the geometry.
6. **`CameraFrame` is part of this task**, because the interface signature needs
   it. Fields: `bytes` (`Uint8List` — `dart:typed_data` is pure Dart, allowed),
   `width`, `height`, `bytesPerRow`, `format`. `format` is an enum
   `CameraFrameFormat { luma8, bgra8888 }` — Android's yuv420 plane 0 is
   `luma8`; iOS bgra8888 is handed over raw and converted inside the detector's
   isolate rather than on the UI thread (T04 explains why).
7. **Interface signature:**
   `Future<Result<DocumentQuad?, AppFailure>> detect(CameraFrame frame)`.
   `Ok(null)` = "no document in this frame" (the normal, common case — locked
   decision #4, never surfaced as an error). `Err` is reserved for a frame that
   could not be processed at all (bad stride, unsupported format).
8. Value equality (`==`/`hashCode`/`toString`) on `UnitPoint` and `DocumentQuad`
   — they will live inside cubit states, so equality drives rebuilds, exactly as
   the existing capture states do.

## Steps
1. `unit_point.dart` — fields, `==`, `hashCode`, `toString`, `lerpTo`.
2. `document_quad.dart` — const ctor, `fromPoints`, `corners` getter (TL,TR,BR,BL
   order), `area`, `isConvex`, `isValid({minArea})`, `boundingRect`, `lerpTo`,
   equality.
3. `camera_frame.dart` — the value object + format enum, with a doc comment
   stating explicitly that frames are never written to disk (locked decision #3).
4. `document_edge_detector.dart` — the interface + doc comment recording that
   `Ok(null)` is not a failure.
5. Tests, then the gate.

## Tests (`document_quad_test.dart`)
- `fromPoints` orders a shuffled square into TL/TR/BR/BL.
- `fromPoints` orders a **rotated** square (~20°) correctly.
- `fromPoints` returns `null` for 3 points / 5 points.
- `boundingRect` of a rotated quad is the min/max box, clamped to 0..1.
- `area` of the unit square is `1.0`; of a half-square, `0.5`.
- `isValid` false for: collinear corners, a self-intersecting (bow-tie) order, a
  quad below `minArea`, duplicate corners.
- `isValid` true for a clean quad and for a mildly perspective-skewed one.
- `lerpTo` at `t = 0`, `t = 1`, `t = 0.5` on each corner.
- Equality: two identical quads are `==` and share a `hashCode`.
