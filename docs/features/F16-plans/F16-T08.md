# F16-T08 · Crop follows the visible guide

> **REVERTED after the T10 device pass (2026-08-31).** This plan shipped, and a
> real device then showed why it should not have: a detection that collapsed to
> a sliver cropped a capture down to a narrow strip and silently discarded ~85%
> of the page. The crop is the static guide box again, and the detected quad is
> painted over it as feedback only. The plan below is kept as the record of what
> was built and why it was undone — do not implement it again without first
> fixing the detector's corner accuracy and frame-to-frame stability.

> Plan for task 8 of [F16](../F16-live-edge-detection.md). If T06's decision #2
> was honoured, this task is mostly *proving* the behaviour rather than building
> it — which is the point.

## Goal
What the user saw framed is what gets kept: when a quad is on screen, the capture
crop is that quad's bounding rect (+ the existing 20% margin); otherwise the
static box, exactly as F15-T12 left it.

## Files

**Modified**
- `lib/features/capture/presentation/screens/camera_capture_screen.dart` —
  hardening `_measureGuideBox`, not rewriting it.
- `test/features/capture/camera_capture_screen_test.dart` (extend)

**Unchanged on purpose**
- `CropToGuideBox` — the 20% margin already lives there (F15 locked decision #2)
  and must not be duplicated or re-tuned here.
- `UnitRect` — `boundingRect` already returns one, clamped.
- `CameraCaptureCubit.capture(guideBox:)` — the signature is already exactly what
  this task needs.

## Design decisions

1. **No new geometry path.** T06 put `frameKey` on the drawn quad's bounding box,
   so `_measureGuideBox` measures the quad automatically. This task's job is to
   verify that, then close the gaps around it. If T06 was implemented some other
   way, fix T06 rather than adding a second measurement here — two ways to
   compute the crop is precisely the drift F15-T12 removed.
2. **Measure the render box, never the state.** Do not compute the crop from
   `state.quad`: the drawn quad lags the state by the smoothing animation
   (T06), and the user framed what they *saw*. Measuring the render box is what
   makes "what was framed is what is kept" literally true, mid-animation included.
3. **Degenerate-quad guard.** If the measured rect is below a minimum fraction of
   the preview (say 10% of either axis), fall back to `UnitRect.full` — the same
   defensive shape the method already uses for an unlaid-out box. A capture must
   never be blocked or reduced to a sliver by a bad detection.
4. **Clamping stays where it is.** `_measureGuideBox` already ends in
   `.clamped()`, so a quad that maps slightly outside the preview (possible under
   a `cover` fit, T05) is already handled.
5. **The margin is not re-tuned for quads.** A detected quad hugs the paper more
   tightly than the static box did, so 20% is, if anything, more generous than
   before — but changing it would alter F15's behaviour on the fallback path too.
   Leave it; note in T10 whether the device pass suggests otherwise.

## Steps
1. Read `_measureGuideBox` alongside T06's frame-key placement and confirm the
   coupling; add a short comment in both places naming the other.
2. Add the minimum-size guard from decision #3.
3. Tests (below) — this is the bulk of the task.
4. If any test shows the measured rect and the drawn quad disagreeing, fix the
   widget, not the screen.

## Tests (`camera_capture_screen_test.dart`)
Using the existing fake cubit / preview-port harness:
- **Quad present** → tapping the shutter calls `capture(guideBox:)` with a rect
  equal to the quad's bounding rect in preview fractions (tolerance for
  subpixel), *not* the static box's rect.
- **No quad** → the guide box passed is the F15-T12 static rect. This is the
  regression test that F16 changed nothing on the fallback path.
- **Quad appears, then drops out** → the next capture uses the static rect again.
- **Mid-animation capture**: change the quad, pump a single frame, then fire the
  shutter → the rect matches the *rendered* interpolated box (decision #2).
- **Degenerate quad** (near-zero area) → `UnitRect.full`, capture still fires.
- **Unmeasurable preview** (preview not laid out) → `UnitRect.full`, unchanged
  from F15.
- End-to-end at cubit level: the rect handed to `CropToGuideBox` is
  `boundingRect.expanded(0.2)` — i.e. the margin is applied exactly once.
