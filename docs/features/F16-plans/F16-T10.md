# F16-T10 · Device verification

> Plan for task 10 of [F16](../F16-live-edge-detection.md). No new code is
> planned here — this task is evidence, and the fixes the evidence forces.

## Goal
Prove on a real device, over real paper, that the guide follows the document,
stops following it cleanly when there is none, that the crop matches what was
shown, and that nothing heats up or drains. Then write down what actually
happened, including what did not work.

## Preconditions
- Device: RMX2001 (the phone used for the F15-T10 pass — reuse it so results are
  comparable), plus one second device if available, ideally a slower one.
- Dev run needs the LAN `SUPABASE_URL` override and a running local Supabase, per
  the project's dev-run setup — otherwise the splash never completes and the
  camera screen is never reached.
- T09's budget instrumentation still in place (or re-enabled behind a temporary
  local flag) so the numbers can be read off the run, then removed.

## The scene list (the task's own acceptance criteria)
Run each with the preview held steady for a few seconds, then moving:

| # | Scene | What to look for |
|---|---|---|
| 1 | **White page on a light desk** | The hard case named in F16's Risks. Record honestly whether it locks on, flickers, or never detects. Never detecting is an acceptable outcome; flickering between the quad and the static box is not — that is a T06/T07 grace-window bug. |
| 2 | White page on a dark surface | Baseline: should be rock solid. If this is not solid, stop and fix before judging anything else. |
| 3 | Angled / perspective (30–45°) | Quad corners follow the real corners; brackets rotate with the paper. |
| 4 | Partially shadowed page | A shadow line across the page must not split the detection into half a page. |
| 5 | Low light | Either detects or falls back — never a frozen stale quad. |
| 6 | Receipt (narrow, glossy) | Small-area subject; check `minAreaFraction` is not rejecting it. |
| 7 | Page with a coloured border | The border must not be preferred over the paper edge. |
| 8 | No document in view (desk, hand, wall) | Falls back to the static box within the grace window, and stays there. |

## Accessibility pass (same run)
- **RTL**: whole UI in Arabic; the overlay geometry must be identical (camera
  space is not mirrored by text direction).
- **Large Text**: system font scale at maximum; the hint pill and shutter still
  fit, the quad is unaffected.
- **High Contrast**: the brackets stay visible; verify state is never conveyed by
  colour alone (the brackets moving onto the paper is the signal).
- If device permissions block changing these via adb, say so explicitly in the
  task row and point at the widget tests that cover them — that is what F15-T10
  did, and it is an honest record rather than a silent gap.

## Crop verification (the actual promise)
For scenes 3, 6 and 8: capture, then inspect the resulting image on the preview
screen. The kept region must be the quad's bounding rect plus the 20% margin —
visibly tighter than the old static box in scene 3, and identical to today's
behaviour in scene 8. Then let `doclens` run and confirm the final image is still
correctly dewarped (it is still the source of geometric truth — locked decision
#1; F16 must not have made its job harder).

## Battery / thermal sanity
- Leave the capture screen open with detection running for **5 minutes**.
- Record before/after battery percentage, and the device temperature via
  `adb shell dumpsys battery` (`temperature` is tenths of a degree C).
- Note whether T09's auto-disable triggered, and after how long.
- Repeat once with detection forced off (comment out the stream start) to have a
  baseline to compare against — a number with no baseline says nothing.

## Privacy re-check (must pass, not optional)
- `grep` the F16 diff for `File(`, `writeAs`, `encodeJpg`, `getTemporaryDirectory`
  on the stream path → must be empty (locked decision #3).
- Confirm no log line prints frame bytes, dimensions tied to content, OCR text, or
  any document content (privacy §7).
- Confirm no user-visible string added by F16 names a provider or claims the
  image never leaves the phone.

## What to write down
Update the F16-T10 row in `F16-live-edge-detection.md` in the same style as
F15-T10: device model, what passed, what did **not** (especially scene 1), any
tuning constant changed as a result, the battery/thermal numbers, and which
checks were covered by widget tests instead of the device because the device
blocked them.
