# F16-T04 · Camera stream plumbing

> Plan for task 4 of [F16](../F16-live-edge-detection.md).

## Goal
Get luma frames out of the running camera, in a format the detector can read, on
both platforms — without changing what the shutter produces.

## Design decisions

1. **`imageFormatGroup` per platform**: `Platform.isAndroid
   ? ImageFormatGroup.yuv420 : ImageFormatGroup.bgra8888`. `jpeg` (today's
   value) cannot be streamed. Keep the choice in one named private getter with a
   comment pointing at this task, so a revert is one line.
2. **`takePicture` is re-verified, not assumed.** The format group affects the
   capture path on some Android devices. Before anything else in this task:
   change *only* the format group, run the existing capture flow on a real
   device, and confirm the produced JPEG is still upright, correctly sized, and
   readable by `ImagePackageCropper`/`doclens`. If it regresses, stop and report
   — the rest of F16 is not worth a broken shutter.
3. **Stream is stopped before the shutter fires and restarted after**, not left
   running. Android's `takePicture` and an active image stream conflict on
   several devices, and locked decision #4 means we take the safe path. Sequence
   inside `capturePhoto()`: `stopImageStream()` (if running) → `takePicture()` →
   return. Restart is the cubit's job (T07), so the service stays stateless about
   *policy*.
4. **Frames are dropped, never queued** (task acceptance). The service holds a
   `bool _detectionInFlight` and a `DateTime _lastDelivered`; a frame arriving
   while a detection is in flight, or sooner than `minFrameInterval` (default
   ~120 ms) after the last delivered one, is discarded immediately without
   allocating. The callback returns a `Future` so the service knows when the
   consumer is done:
   `Future<Result<void, AppFailure>> startFrameStream(Future<void> Function(CameraFrame) onFrame)`.
5. **Plugin types stop here.** `CameraImage` is mapped to the domain's
   `CameraFrame` inside this file — plane 0 + `bytesPerRow` for yuv420, the raw
   BGRA buffer for bgra8888 (conversion happens in T03's isolate). Nothing above
   the data layer ever sees a `CameraImage`.
6. **Zero copies on the UI thread.** Hand `plane.bytes` straight through; do not
   convert, crop, or clone on the main isolate.
7. **Nothing touches disk** (locked decision #3) — assert this in review: no
   `File`, no encode, no temp path anywhere in the stream path.
8. **The epoch guard extends to the stream.** `dispose()`/re-`initialize()` must
   stop the stream first; a stream callback that fires after the epoch moved on
   is dropped, exactly like the existing in-flight-initialize guard.
9. **Failure is silent** (locked decision #4): `startFrameStream` returning `Err`
   (unsupported format, stream won't start) is not shown to the user — T07 just
   leaves the static box up.

## Steps
1. **Format flip alone**, then a device run of the existing capture flow (see
   decision #2). Commit-worthy checkpoint even before the stream exists.
2. Add the `CameraService` methods + their doc comments.
3. Implement `startFrameStream` / `stopFrameStream` with the throttle-and-drop
   gate and the epoch guard.
4. Extract the `CameraImage → CameraFrame` mapping into a **static, plugin-typed
   but pure** function so it can be unit-tested with a hand-built fake
   `CameraImage`-shaped input, or — if the plugin's types resist construction in
   a test — into a function taking `(List<Plane>-equivalent primitives)` and test
   *that*. Do not skip testing the stride/format mapping; it is the part that
   silently produces garbage.
5. Wire the shutter interlock in `capturePhoto()`.
6. Add the two use cases (thin, `call()`-style, matching the existing ones).
7. Device sanity: log *frame arrival counts only* (never bytes, never content)
   behind a temporary debug flag, confirm frames arrive and are dropped under
   load, then remove the logging before committing.

## Tests
- Frame mapping: yuv420 plane with padded `bytesPerRow` → `CameraFrame` carries
  the stride, not the width.
- Frame mapping: bgra8888 → `format` is `bgra8888`, `bytesPerRow` = 4×width.
- Throttle: two frames delivered back-to-back while the first callback is still
  pending → the second is dropped (callback invoked once).
- Throttle: a frame arriving inside `minFrameInterval` is dropped.
- Interlock: `capturePhoto()` stops the stream before calling `takePicture` (fake
  controller / recorded call order).
- Existing `camera_capture_cubit_test.dart` and `camera_capture_screen_test.dart`
  still pass untouched — the capture path's contract has not moved.
