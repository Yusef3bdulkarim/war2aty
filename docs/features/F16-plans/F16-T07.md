with the camera, stop it for the shutter — and exposes the current quad as state.

## Design decisions

1. **State shape:** `CameraReady` gains `final DocumentQuad? quad` (default
   `null`) with proper value equality — it is no longer a bare marker. Keep
   `CameraCapturing`/`CameraCaptured`/`CameraCaptureError` as they are; a quad is
   meaningless once the shutter has fired. Every existing `const CameraReady()`
   call site keeps compiling if the parameter is optional-positional-free and
   defaulted — check the screen's `state is CameraReady` branches, which are
   type-tests and so unaffected.
2. **Quad in state is in *sensor* space.** The cubit must not know about widget
   geometry, so T05's `mapToPreview` is applied in the **screen**, using the
   orientation/mirror data carried on the frame and echoed in state. Concretely:
   `CameraReady` carries `quad` plus `sensorOrientation`/`isMirrored`, and the
   screen maps immediately before handing it to `ViewfinderFrame`. This keeps
   the cubit free of preview-rect knowledge and is exactly the split
   `_measureGuideBox` already uses.
3. **Lifecycle, tied to the camera's, using the existing `_generation` guard:**
   - `start()` → on `Ok` from `initializeCamera` → `emit(CameraReady())` then
     `startFrameStream(_onFrame)`. A failed stream start is swallowed (locked
     decision #4) — the state stays `CameraReady(quad: null)`.
   - `capture()` → `stopFrameStream()` **before** `_capturePhoto()`; the service
     also guards this (T04 decision #3), belt and braces, and the cubit is where
     the ordering is testable.
   - `suspend()` and `close()` → `stopFrameStream()` before `_disposeCamera()`.
   - Every stale-generation early-return path must also stop the stream, or a
     backgrounded app keeps a detector running.
4. **`_onFrame` is the only new async path:**
   ```
   Future<void> _onFrame(CameraFrame frame) async {
     if (isClosed || state is! CameraReady) return;
     final generation = _generation;
     final result = await _detectDocumentEdges(frame);
     if (isClosed || generation != _generation || state is! CameraReady) return;
     _publish(result.valueOrNull);   // Err is treated exactly like null
   }
   ```
   The service (T04) guarantees no second frame arrives while this is pending, so
   there is no queue to manage here.
5. **Hold-last / grace window lives here** (T06 decision #3): a `_missStreak`
   counter; `null` results increment it and only when it exceeds
   `_maxMisses` (default 5, ~600 ms at the T04 throttle) does the cubit emit
   `quad: null`. A non-null detection resets it to 0. Pure counting, no timers —
   deterministic in tests.
6. **Emit only on change.** `_publish` compares against the current state's quad
   with `==` and skips the `emit` when equal, so a still camera does not rebuild
   the tree ~8×/second.
7. **DI:** `..registerLazySingleton<DocumentEdgeDetector>(DartDocumentEdgeDetector.new)`
   next to the other capture services, `..registerFactory<DetectDocumentEdges>(…)`,
   and inside the existing `CameraCaptureCubit` factory add
   `startFrameStream: StartFrameStream(camera)`, `stopFrameStream:
   StopFrameStream(camera)`, `detectDocumentEdges: getIt()` — following the
   comment already there about the camera instance being shared with `preview`.

## Tests (`camera_capture_cubit_test.dart`, extending the existing fakes)
- Successful `start()` starts the frame stream; a failed `initialize()` does not.
- A frame producing a quad emits `CameraReady(quad: …)`.
- An identical consecutive detection emits **once** (no duplicate states).
- `_maxMisses` misses in a row keep the last quad; the miss after that emits
  `quad: null`; a detection in between resets the streak.
- `Err` from the detector behaves exactly like `null` — never a
  `CameraCaptureError`, never a user-visible failure (locked decision #4).
- `capture()` stops the stream **before** taking the photo (recorded call order).
- `suspend()` and `close()` stop the stream.
- A frame whose detection resolves after `suspend()` (stale generation) emits
  nothing.
- A frame arriving while `state is CameraCapturing` is ignored.
- Existing F15 tests (temp-file cleanup, generation guards) still pass unchanged.
