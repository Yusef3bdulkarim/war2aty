# F16-T03 · Pure-Dart detector

> Plan for task 3 of [F16](../F16-live-edge-detection.md). Still no wiring — this

## Goal
`DartDocumentEdgeDetector implements DocumentEdgeDetector`: luma bytes in, a
`DocumentQuad?` out, cheap enough to run on preview frames, deterministic enough
to unit-test without a camera. No new package (locked decision #2), nothing
touches disk (locked decision #3).

**Modified:** none.

## Design decisions

1. **Algorithm and isolate are separate files.** Tests call the pure function
   directly and synchronously — no isolate flakiness, no timing in tests, and
   T09 can swap `Isolate.run` for a persistent worker without touching a line of
   tested logic.
2. **Pipeline** (fixed order, each step a private static function):
   1. **Sample-downscale** to a target of ~160×120 (`targetWidth` in tuning) with
      integer strides, honouring `bytesPerRow` — a plane's stride is *not* its
      width, and getting this wrong is the classic skewed-image bug. For
      `bgra8888` the same pass reads 4 bytes/pixel and converts
      (`0.299R + 0.587G + 0.114B`), so the iOS conversion costs nothing extra
      and happens inside the isolate rather than on the UI thread.
   2. **Blur** — one 3×3 box blur pass (separable, two 1-D passes) to kill sensor
      noise. Cheap and enough at this size.
   3. **Sobel** — gradient magnitude `|gx| + |gy|` (L1, not the square root; the
      threshold is relative anyway).
   4. **Binarise** — threshold at a *percentile* of the magnitude histogram
      (`edgePercentile`, default ~0.92) rather than a fixed value, so the same
      code copes with a bright desk and a dim room. Falls out of a 256-bucket
      histogram, no sorting.
   5. **Largest component** — union-find (8-connected) over the edge pixels;
      keep the component with the most pixels. Rejects clutter and the text
      inside the page, which forms many small components rather than one frame.
   6. **Convex hull** — Andrew's monotone chain over that component's pixels.
   7. **Reduce hull → 4 corners** — repeatedly drop the hull vertex whose removal
      loses the least area until 4 remain. Deterministic, no RANSAC, no random
      seed. Then `DocumentQuad.fromPoints`.
   8. **Validate** — `quad.isValid(minArea: tuning.minAreaFraction)`; also reject
      a quad whose corners are within `edgeMargin` of the frame border on all
      sides (that is the desk, not the page). Fail → `null`.
3. **`null` is a normal outcome, not an error** (locked decision #4). `Err` is
   only for a frame whose dimensions/stride are inconsistent with its byte length.
4. **`DetectorTuning`** is a const class with named defaults:
   `targetWidth`, `edgePercentile`, `minAreaFraction`, `minComponentPixels`,
   `borderMarginFraction`. Injected through the detector's constructor so tests
   pin exact values and T09/T10 can retune without touching the algorithm.
5. **Isolate strategy** — start with `Isolate.run`, matching
   [`ImagePackageRotator`](../../../lib/features/capture/data/services/image_package_rotator.dart),
   and pass the bytes as `TransferableTypedData` to avoid a copy. **Measure spawn
   cost in T09**; if it dominates the frame budget, swap in a long-lived worker
   isolate there — the split in decision #1 is what makes that a local change.
6. **Never log frame content** (privacy §7). No debug dumps of pixels, no
   writing a debug image to disk, not even behind a flag.

## Steps
1. `synthetic_luma.dart` first — a `syntheticFrame({page, rotationDegrees,
   pageLuma, backgroundLuma, noise})` helper that fills a `Uint8List` by
   rasterising a (possibly rotated) filled polygon. Tests are only as good as
   this builder, so build it first and assert on it.
2. Algorithm file, step by step, each private function testable through the
   public entry `DocumentEdgeAlgorithm.detect(CameraFrame, DetectorTuning)`.
3. Detector wrapper: frame → `TransferableTypedData` → `Isolate.run` → quad,
   `try/catch` → `Err(ImageProcessingFailure())` at the boundary (§3 of the
   global rules: catch at the data boundary, classify, never throw upward).
4. Tests, then the gate.

## Tests
Against synthetic buffers, per the task's acceptance criteria — **no real
photos**, so the suite stays deterministic:
- **Clean page**: bright rect (luma 200) on dark background (luma 40), centred →
  quad found, corners within a few percent of the truth, `boundingRect` matches.
- **Rotated page** (~15° and ~35°) → quad found, corners still ordered TL/TR/BR/BL
  after `fromPoints`.
- **No page**: uniform buffer, and uniform + noise → `null`, not `Err`.
- **Low contrast**: page luma 200 on background 190 → assert the *documented*
  behaviour (whatever it is — likely `null`); this test is the honest record of
  the known weak point named in F16's Risks, so it asserts a decision, not a hope.
- **Page filling the whole frame** (bleeds to the border) → rejected by the
  border rule.
- **Stride handling**: same image with `bytesPerRow = width` and with
  `bytesPerRow = width + 32` padding → identical quad. This is the regression
  test for the stride bug.
- **bgra8888** input of the same scene → same quad as the luma8 version, within
  tolerance.
- **Determinism**: the same frame twice → identical quad.
- **Tuning is honoured**: raising `minAreaFraction` above the page's area turns a
  found quad into `null`.
- Wrapper test: byte length shorter than `bytesPerRow * height` → `Err`.
